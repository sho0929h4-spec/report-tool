## 3. ログイン・認証方式

- `index.html` 内にハードコードされた `PASSWORD` 定数と入力値を比較（`doLogin()`、L405付近）。
- 一致で `localStorage.rauth='1'` を立てて画面切替。次回以降は自動ログイン。
- **サーバー検証なし＝ソースを見れば誰でも通れる簡易ガード。** 個人利用前提では許容。新システムでは Supabase Auth（サーバー側検証 + RLS）を使う。既存ツールの認証はそのまま温存。

## 4. 報告書入力フォーム

- 入力項目: 会社名（localStorage記憶）/ 案件No / 物件名 / 号室 / 作業区分 / 作業日 / 作業時間 / 状況（f-f1）/ 応急対応（f-f2）/ 今後の対応（f-f4）ほか。**住所フィールドは無い。**
- 漏水系の選択UI（「漏れている（継続的/断続的）」等）は直近コミットで追加済み。
- 自由記載 textarea 3箇所に音声入力ボタン（🎤）。Chrome系のみ動作、非対応ブラウザでは自動無効化。
- `collectData()`（L591）がフォーム全体を1つのJSONレコードに集約。

## 5. 写真アップロードと保存方式

- `<input type="file" accept="image/*" multiple>` + ドラッグ&ドロップ。
- FileReader → dataURL化 → メモリ上の `photos[]` 配列（キャプション・フェーズ付き）。
- PDF出力時に `compressImage()`（canvas再描画、品質指定）で圧縮。
- 保存時は dataURL のまま IndexedDB レコード内に埋め込み（`collectData()` → `photos: photos.map(...)`）。
- サーバー送信なし。**通信・再送の概念自体が存在しない**（指示書§3の「再送」は新システム側の新規要件）。

## 6. PDF生成方式

- `downloadPDF()`（L712）: 報告書プレビューの各ページを html2canvas（scale:2）→ JPEG(0.92) → jsPDF A4縦 に貼り付け、`【報告書】◯◯.pdf` で保存。
- 完全クライアント処理。画像PDFのため文字検索不可・ファイルサイズ大（既知の割り切り）。
- `@media print` CSSもあり、ブラウザ印刷にも対応。
- **新システムの帳票（社内日報/クライアント報告書）はこの処理をコピーして再利用可能。**

## 7. 履歴保存方式

- `dbSave()` は `.add()`（常に新規ID追加）。履歴一覧から 編集（histEdit）/ PDF再出力（histPDF）/ 削除（histDelete）。
- 更新は「新レコード追加」になる設計（上書きなし）。

## 8. データの永続化方式

- IndexedDB は**ブラウザ・端末ごと**。機種変更・ブラウザ変更・キャッシュ消去でデータ消失。
- バックエンドなし。バックアップ機構なし。

## 9. GitHub Pages デプロイ方式

- GitHub Actions なし（`.github/` 不在）→ **main ブランチ直配信**。`git push origin main` ＝即デプロイ。
- 現在ローカルは origin/main より **4コミット先行**:
  - `4278b7f` feat: キーボード操作対応 ← **push すると本番の既存ツールに反映される（未レビュー）**
  - 残り3つは docs のみ（本番挙動に影響なし）
- 本番の index.html は 884 行（= d0a091f）。

## 10. 既存データの移行可否

- **可能。** IndexedDB レコードは自己完結JSON（写真もdataURLで内包）なので、新システム側に「エクスポート→案件に関連付けてインポート」機能を実装すれば移行できる（計画2で実装）。
- 指示書§2「単独利用時に生成した報告書を後から親システムの案件に関連付ける」も同じ仕組みで実現。
